# Руководство пользователя и интегратора

## Настройки

`ysk init` создаёт `~/.config/you-should-know/config.json`. Переменная `XDG_CONFIG_HOME` заменяет каталог `~/.config`. Существующий файл не перезаписывается.

```json
{
  "observer": {
    "language": "auto",
    "minSteps": 6,
    "minIntervalMs": 120000,
    "maxChecksPerSession": 20,
    "maxChecksPerHour": 8
  },
  "provider": { "type": "codex" }
}
```

CLI принимает `--config /absolute/path/config.json`. Установленные хуки используют стандартный пользовательский файл. Репозиторий не может переопределить исполняемый файл провайдера, адрес API или источник ключа.

Для конкретного проекта создай `.you-should-know.json` в корне рабочего каталога. Это непосредственно объект настроек наблюдателя:

```json
{
  "language": "ru",
  "maxChecksPerHour": 3,
  "minIntervalMs": 300000
}
```

Приоритет: встроенные значения → пользовательский файл → настройки проекта → `options` плагина OpenCode. Переопределяются только явно указанные ключи. Неизвестные параметры отклоняются.

| Ключ                  | По умолчанию | Допустимые значения                                    |
| --------------------- | ------------ | ------------------------------------------------------ |
| `enabled`             | `true`       | Логическое значение                                    |
| `language`            | `auto`       | `auto`, `en`, `ru`, `zh`                               |
| `minSteps`            | `6`          | Целое, 1–100                                           |
| `minIntervalMs`       | `120000`     | Целое, 0–3 600 000                                     |
| `maxChecksPerSession` | `20`         | Целое, 1–200                                           |
| `maxChecksPerHour`    | `8`          | Целое, 1–120, на проект                                |
| `timeoutMs`           | `45000`      | Целое, 1 000–180 000                                   |
| `maxContextChars`     | `40000`      | Целое, 2 000–120 000                                   |
| `maxMessageChars`     | `6000`       | Целое, 500–20 000                                      |
| `minConfidence`       | `0.85`       | 0,5–1; самооценка модели, не калиброванная вероятность |
| `retentionDays`       | `30`         | Целое, 1–365                                           |

Лимит символов относится к тексту сообщений. Дополнительно отправляются инструкции, JSON-структура, известные темы и краткое содержание недавних заметок. Это не лимит токенов или стоимости.

## Провайдеры

### Нативный OpenCode

Плагин вызывает `ctx.experimental.generate.text` с моделью текущей сессии: без инструментов, состояния диалога и записи в историю. Настройка `provider` отдельного CLI не меняет модель нативной интеграции.

Серверные хуки не ждут завершения генерации. Наблюдаются основные сессии, дочерние пропускаются. Новое сообщение отменяет запрос предыдущего хода внутри процесса. RPC и уведомления привязаны к рабочему каталогу и сессии.

Интерфейс Desktop следует языку приложения, если язык не указан явно. Заметки с `language: "auto"` следуют последнему сообщению пользователя. TUI выбирает язык интерфейса по настройке или `LANG`.

### Аккаунт Codex

```json
{
  "provider": {
    "type": "codex",
    "executable": "codex"
  }
}
```

Нужны Codex **0.162.0+** и авторизация (`codex login`). Необязательный `model` выбирает доступную аккаунту модель; иначе используется модель Codex по умолчанию. Если Codex отсутствует в PATH клиента, укажи абсолютный `executable`.

Каждая проверка запускает `codex app-server --stdio` в пустом временном каталоге и создаёт эфемерный read-only поток. Инструменты, хуки, плагины, MCP, память и веб-поиск отключаются; рабочие корни и среды не передаются. Попытка использовать инструмент или запросить разрешение завершает проверку. Процесс наследует окружение CLI для авторизации: это не песочница уровня ОС. Временный каталог затем удаляется.

Расходуются лимиты настроенного аккаунта/провайдера Codex. API app-server зависит от версии. `ysk doctor` проверяет версию, но не выполняет реальную генерацию; статус входа проверяется через `codex login status`.

### OpenAI-совместимый API

```json
{
  "provider": {
    "type": "openai-compatible",
    "model": "MODEL_ID",
    "baseUrl": "https://api.openai.com/v1",
    "apiKeyEnv": "OPENAI_API_KEY"
  }
}
```

Установи указанную переменную окружения там, где запускается клиент. Вместо `MODEL_ID` используй доступную модель. Endpoint должен поддерживать Chat Completions и `response_format: { "type": "json_object" }`. Инструменты не передаются. Для официального OpenAI используется `max_completion_tokens`, для остальных — `max_tokens`. Частичной совместимости API может быть недостаточно.

Ключ обязателен и для локальных API; если локальный сервер игнорирует авторизацию, можно использовать несекретную заглушку. Настройки проекта не задают ключи. HTTP-перенаправления отклоняются, чтобы не передавать ключ другому endpoint.

### Anthropic API

```json
{
  "provider": {
    "type": "anthropic",
    "model": "MODEL_ID",
    "apiKeyEnv": "ANTHROPIC_API_KEY"
  }
}
```

По умолчанию используется Messages API `https://api.anthropic.com/v1/messages`, Bearer-авторизация и версия `2026-10-21`. Необязательный `baseUrl` заменяет базовый адрес `/v1`. Нужна модель с текстовым ответом. Используются API-ключ и API-биллинг, а не подписка Claude Code.

## Хуки

| Клиент      | Файл                                                             |
| ----------- | ---------------------------------------------------------------- |
| Codex       | `$CODEX_HOME/hooks.json` или `~/.codex/hooks.json`               |
| Claude Code | `$CLAUDE_CONFIG_DIR/settings.json` или `~/.claude/settings.json` |

`ysk install <host>` добавляет четыре события:

- `PostToolUse` и `Stop`: асинхронное чтение ограниченного транскрипта и возможный запрос модели; ответ всегда `{}`.
- `UserPromptSubmit`: синхронно делает предыдущий результат неактуальным и доставляет одну локальную заметку через `systemMessage`; без генерации.
- `SessionEnd`: делает ожидающие результаты неактуальными.

Для Codex включи хуки, например `codex --enable hooks`. Если ход содержит меньше `minSteps` событий с результатами инструментов, проверки не будет даже на `Stop`. Параллельные результаты считаются так, как представлены в транскрипте.

Фоновые ответы не добавляют инструкций основному агенту. Асинхронные хуки Claude не показывают `systemMessage` напрямую, поэтому доставка выполняется при следующем сообщении. `ysk watch` показывает заметки раньше. Конкретное отображение зависит от интерфейса клиента.

Установщик идемпотентен, записывает файл атомарно и сохраняет первую резервную копию как `<config-file>.before-ysk`. Некорректный JSON и неожиданная структура хуков не перезаписываются. Удаление убирает записи с `--managed-by-ysk`, не заменяя текущие настройки старой копией. Команда хука использует `node` из PATH и абсолютный путь к `dist/cli.js`.

Процессы хуков разделяют дисковые резервации. Новое сообщение отменяет актуальность резервации, чтобы устаревшая заметка не сохранилась. В отличие от OpenCode внутри одного процесса, уже запущенный запрос другого процесса может продолжаться до ответа или таймаута и расходовать лимиты.

## CLI и MCP

`ysk --help` выводит команды. `notes`, `show`, `feedback`, `doctor` и `check` поддерживают `--json`. `--session` фильтрует `notes` и `watch`. Варианты обратной связи: `known`, `helpful`, `dismissed`, `irrelevant`.

`known` и `helpful` запоминают тему в проекте. Повторы всех предложенных тем подавляются, пока хранятся заметки. Непрочитанная заметка истекает с началом нового наблюдаемого хода; после нескольких проигнорированных заметок пропускается больше подходящих проверок. Обратная связь сбрасывает это замедление. `pause` сохраняется после перезапуска.

Для явной проверки передай JSON через stdin:

```sh
ysk check --manual --json < integrations/observation.json
```

Это настоящий запрос модели. `--manual` пропускает частоту, задержку и замедление, но не бюджет, паузу, неизменившийся контекст, активный запрос и правило одной заметки на ход.

Вход содержит `host`, `sessionId`, `turnId`, `step`, `messages`. Сообщение содержит уникальный `id`, `role` (`user`, `assistant`, `tool`) и `text`. Передавай цель пользователя вместе с релевантными результатами агента. CLI принимает до 2 МБ.

| Интерфейс MCP  | Поведение                                                       |
| -------------- | --------------------------------------------------------------- |
| `ysk_observe`  | Наблюдение без `host`, до 100 сообщений; возможен запрос модели |
| `ysk_notes`    | Необязательный `sessionId`; чтение заметок                      |
| `ysk_feedback` | `id` и `feedback`; явная обратная связь человека                |
| `ysk://notes`  | JSON-ресурс с заметками проекта                                 |

MCP не подписывается автоматически на диалог другого клиента. Клиент выбирает момент проверки и передаёт `step`. При запуске сервера укажи `--cwd`, чтобы область проекта была однозначной. В stdout сервера идут только протокольные сообщения.

## Хранение и поток данных

```text
Диалог клиента
  → нормализация текста и ограничение контекста
  → скрытие распространённых секретов
  → резервация проверки в бюджете проекта
  → текстовый запрос модели
  → проверка схемы, уверенности, цитат и актуальности
  → устранение повторов и сохранение заметки
  → интерфейс / следующий prompt / watch / MCP
```

Состояние: `$XDG_STATE_HOME/you-should-know` или `~/.local/state/you-should-know`. `YSK_DATA_DIR` заменяет корневой каталог. Канонический путь workspace преобразуется в `projects/<path-hash>/state.json`. Символьные ссылки используют общее состояние; разные каталоги и worktree — отдельное, даже внутри одного репозитория. Запускай CLI из того же рабочего каталога, что использует клиент.

Сохраняются заметки с цитатами, обратная связь, известные темы, ID сессий и ходов, хеши, время, бюджеты и резервации. Полные транскрипты, рассуждения модели, ключи и сырые ответы провайдера не сохраняются. Сами заметки могут содержать приватную информацию проекта.

На проект хранятся до 100 заметок, 100 тем и 64 недавно использованных записей сессий. Сессионные бюджеты зависят от сохранённых записей. Очистка происходит при проверке, чтении, доставке и обратной связи. Отдельного фонового удаления нет: файлы неиспользуемого проекта остаются до следующего обращения или ручного удаления.

Новые каталоги и файлы получают права `0700`/`0600` в POSIX; в Windows действуют наследуемые ACL. Запись защищена межпроцессной блокировкой и атомарной заменой. Повреждённое или неподдерживаемое состояние сохраняется, а не молча сбрасывается. `uninstall` оставляет данные. Чтобы удалить их, останови наблюдатели и удали нужный каталог проекта из хранилища, не затрагивая соседние проекты.

## Диагностика

| Симптом                                     | Что проверить                                                                                     |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Нет заметок                                 | Это нормально. Проверь `enabled`, `ysk resume`, частоту, бюджет и изменение контекста.            |
| `ysk` не найден                             | Выполни `npm link` после сборки; проверь глобальный bin npm в PATH.                               |
| Плагин OpenCode недоступен                  | Укажи каталог, собери `dist`, проверь статус плагина. Для Desktop нужна глобальная запись.        |
| Хуки Codex не работают                      | Версию Codex, флаг `hooks`, соответствие `CODEX_HOME` окружению клиента.                          |
| Хуки Claude не работают                     | Поддержку async, провайдер и `CLAUDE_CONFIG_DIR`.                                                 |
| Заметка есть в `watch`, но ещё не в клиенте | Доставка через хук происходит при следующем сообщении; интерфейсы отличаются.                     |
| HTTP `provider_error`                       | `ysk doctor`, ID модели, переменную ключа, endpoint и квоту. Тело ошибки провайдера не выводится. |
| `invalid_response`                          | Модель нарушила строгую схему; заметка не сохраняется.                                            |
| `unsubstantiated`                           | Цитаты нет в выбранном контексте либо ответ не прошёл проверку скрытия секретов.                  |
| Ошибка состояния                            | Сохрани резервную копию и проверь каталог состояния; повреждённые файлы не удаляются.             |

## Совместимость и проверки

Целевые API: OpenCode V2 (`@opencode/plugin ~2.2.6`), app-server и хуки Codex `0.162.0`, MCP SDK `1.x`. API Desktop и Codex могут меняться. После обновлений запускай package smoke-тест.

Автоматические проверки охватывают ядро, адаптеры, subprocess/HTTP, MCP и установку без dev-зависимостей. Реальная авторизация Codex и сервер/RPC OpenCode проверены на macOS с синтетическими данными. Отображение хуков Claude Code и поведение хостов на других ОС зависят от версии клиента; переносимые тесты пакета не равнозначны полной проверке интерфейсов всех хостов.
