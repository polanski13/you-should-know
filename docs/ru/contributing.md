# Участие в разработке

Спасибо за помощь в создании полезного и ненавязчивого наблюдателя.

## Подготовка

Нужны Node.js 22.18+ и npm. После клонирования:

```sh
npm ci
npm run check
npm run test:package
```

`check` проверяет строгую типизацию, тесты, обе сборки и форматирование. Для форматирования используй `npm run format`. Тесты работают с синтетическими данными и локальными фикстурами, без аккаунтов и API-ключей. `test:package` требует доступ к реестру npm для установки runtime-зависимостей во временный каталог, но не обращается к модели.

## Структура

| Каталог                     | Ответственность                                                 |
| --------------------------- | --------------------------------------------------------------- |
| `src/core`                  | Схемы, контекст, промпт, расписание, проверка цитат и состояние |
| `src/providers`             | Транспорт Codex app-server и HTTP                               |
| `src/opencode`              | Сервер, RPC, Desktop и TUI                                      |
| `src/adapters`              | Транскрипты, хуки, установщик и MCP                             |
| `src/cli.ts`                | Команды и отказоустойчивая точка входа хуков                    |
| `test`                      | Детерминированные модульные и интеграционные тесты              |
| `scripts/smoke-package.mjs` | Проверка установки production-пакета                            |
| `integrations`              | Примеры настроек и входных данных                               |

Ядро не импортирует SDK клиентов. Провайдеры реализуют `ModelProvider`, хранилища — `StateStore`. SDK OpenCode нужен только для разработки: Node-адаптеры используют type-only импорты, а Desktop получает общие UI-модули от хоста. Сохраняй эти границы.

## Проверки и pull request

Добавляй регрессионные тесты наблюдаемого поведения: дубли запросов, устаревшие результаты, потерянные записи, утечки контекста, неправильное объединение хуков и ошибки протокола. Изменение промпта требует примеров, где заметка нужна и где следует промолчать. Постоянное появление заметок не является успехом.

Изменения интеграций проверяй в поддерживаемой версии хоста и на фикстурах. Для живых проверок используй синтетический диалог и указывай версию клиента. Не коммить реальные транскрипты, ключи, локальные настройки и чужую закрытую реализацию.

В PR объясни проблему, изменение поведения и способ проверки. Не смешивай несвязанные изменения. Пользовательскую документацию обновляй на английском, русском и китайском; основной текст — английский. Переводы должны сохранять ограничения, а не только команды установки.

Выбирай понятные имена, поясняй только неочевидные ограничения. Ошибки не должны раскрывать тело ответа провайдера или приватный диалог. В баг-репорте укажи клиент и версию, ОС, Node, ожидаемое и фактическое поведение и минимальный синтетический пример. Для чувствительных уязвимостей используй приватный канал GitHub, если он доступен; не публикуй секреты в issue.

## Подготовка релиза

1. Обнови версию, changelog и lockfile.
2. Выполни `npm run check` и `npm run test:package` в чистом checkout.
3. Проверь `npm pack --dry-run` и `npm audit --omit=dev`.
4. Проверь загрузку в OpenCode и запрос Codex на синтетических данных.
5. Публикуй только после явного решения сопровождающего. Пока пакет не доступен, документация должна описывать установку из исходников.

SDK OpenCode имеет большой граф dev-зависимостей. Отдельные production-аудит и установка гарантируют, что инструменты SDK не станут runtime-зависимостями случайно. CI не делает авторизованных запросов к модели и не публикует пакеты автоматически.

На 10 ноября 2026 года полный dev-аудит сообщает об умеренных уязвимостях транзитивных `glob` и `minimatch` в SDK ([GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4), [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)). SDK пока закрепляет затронутые major-версии; в production-установке этих пакетов нет. Проверяй обновления SDK вместо принудительных несовместимых overrides ради чистого отчёта.
